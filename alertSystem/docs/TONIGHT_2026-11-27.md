## M1 design (pre-registered)

- **Taxonomy (M1a).** Start from the 8 keyword groups. Add entity tags found in the bet questions (companies,
  tickers, people, institutions, countries, commodities) by term frequency × volume, and discover new topic tags
  by clustering question text (TF-IDF → NMF topics); each topic is named from its top terms and kept only if it
  covers ≥ 20 bets. Every tag is saved with its criteria (keywords / patterns, source, size) in
  `data/app/taxonomy.json`, versioned.
- **Tagger (M1b).** One-vs-rest logistic regression on word and character n-grams of the question (+ event
  title / slug where available). Labels: the rule tags. Test: time split (train on bets that closed before the
  split, test after). Report per-tag precision / recall vs the rules, and a hand-check sample. **Pass:** on new
  bets, macro F1 ≥ 0.8 vs rules and ≥ 10% more bets tagged than the rules at the same precision (the rules miss
  paraphrases).
- **Links (M1c).** A tag links to a holding if (a) the holding's sector / industry / ETF table maps to it (as
  now) or the tag names the holding, and (b) the doc 13 same-hour test on that holding's history gives an effect
  > 0. An ML link score (per tag × holding effect, shrunk toward the tag average) ranks links. **Pass (the one
  that counts):** the same-hour effect with learned links is ≥ the effect with keyword links (doc 13: +7%,
  doc 14 direct: +10.6%), on the same hours. M1's earlier failure was "worse than keywords"; this is the
  retest.

## M4 design (pre-registered)

- **Rows:** holding × hour (research holdings, no crypto), only hours after the bet data starts.
- **Outputs:** (1) **main**: is this hour a top-20% move for the holding (its own size, by hour of day)?
  (2) size: |return| ÷ normal; (3) direction (expected to fail).
- **Baselines (the "current pure statistics"):**
  - B0 = today's app rule: probability of a big move = historical rate after a linked jump (25%) vs without (18%);
  - B1 = autoregressive volatility (HAR: last 1 h, 1 day, 1 week mean of |return| ÷ normal) + VIX level and change
    + hour of day + open flag. **B1 is the bar to beat.**
- **Jump-stream features (added on top of B1):** linked jumps in the last 1 / 6 / 24 h (counts, max size,
  signed sum), split by tag and by direct vs loose link; time since the last jump; a decayed jump intensity;
  overnight jump count before the open; all-market jump count (news day); wallet features where trades exist
  (C0 / C2 surge, $5k+ net flow, wallets on several linked bets); sector gauge (V3) change.
- **Checks before fitting:** correlation matrix and VIF; features with VIF > 10 are merged or ridge-penalised.
- **Models:** logistic (ridge) → gradient-boosted trees (sklearn HistGradientBoosting) → only if those gain,
  a small sequence model.
- **Validation:** walk-forward by month (train on everything before, test on the next month), never shuffled;
  95% CI on the improvement by day-block bootstrap.
- **Pass:** for output (1), AUC and Brier skill of B1 + jumps > B1 with CI above 0 (and > B0). Same for the
  overnight → open subset. Output (2): lower error, CI above 0. Output (3): accuracy CI above 50%.
- **If it passes:** the app shows "chance of a big move" from M4 in Watch the open and the holding drawer
  instead of the fixed +12% / +16%. If not: report it plainly, keep the TODO open with what to try next.

## Overnight model search (added 17:40, at the user's request)

Keep trying until the user wakes up, the credits run out, or a model passes clearly; keep going after a pass to
see if it holds or improves.

**Guard against "found it by trying many times".** The more models are tried, the more likely one wins by luck.
So the data is split three ways by time, never shuffled:
1. **Train** — the oldest data.
2. **Validation** — walk-forward months after train; every variant is scored here and the best are picked here.
3. **Lock box** — the newest ~20% of days, touched **once**, at the end, only by the final 1–3 picked models
   and the baselines. Only the lock-box result is reported as the answer. Every variant tried is listed in the
   log with its validation score (no hiding the losers).

**What gets varied (one change at a time, logged as runs `m4_r01`, `m4_r02`, …):**

| Axis | Options |
|---|---|
| Target | big move (top 20%) this hour; next 3 hours; the open only; size (\|return\| ÷ normal); direction |
| Preprocessing | raw counts vs log counts; per-holding standardising; winsorising; jump windows 1/3/6/24 h vs decayed intensity (half-life 2/6/24 h); tags as families vs single tags; with / without price-level bets; 60-min vs 5-min (V6) outcome |
| Features | B1 baseline (HAR + VIX + calendar + holding); + linked jumps; + all-market jumps (news day); + direct-link split; + tag families; + wallet signals (C0 / C2 surges, $5k+ flow, multi-bet wallets); + sector gauges (V3) |
| Models | logistic (ridge / lasso); gradient-boosted trees; random forest; small neural nets (MLP); sequence models on the hourly stream (GRU / small temporal CNN) only after trees show signal |
| Multicollinearity | correlation matrix + VIF before every linear model; merge or penalise features with VIF > 10 |

**Pass rule (unchanged):** on the lock box, B1 + jump features beat B1 with the 95% CI of the AUC and Brier-skill
gain above 0, for all hours or for the open. "Significantly well" = this rule, not a validation score.
